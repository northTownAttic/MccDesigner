# MCC Designer MVP

C# / .NET 8 Windows WPF + MVVM. Open `MccDesigner.sln` in Visual Studio 2022 with the .NET desktop workload, build, then press F5.

## 전체화면과 설정 미리보기
- 메인 화면은 **1920×1080 기준의 고정 전체화면**으로 시작합니다. 창 테두리와 크기 조절을 없애고, 다른 해상도/DPI에서는 같은 화면 비율로 맞춥니다. 운영체제의 해상도를 바꾸지는 않습니다.
- 상단의 **최소화 / 종료** 버튼을 사용할 수 있으며 Alt+F4로도 종료할 수 있습니다.
- 설비 설정 창은 **좌측 치수 입력 / 우측 초기 위치 미리보기**입니다. 입력 중 유효한 값은 잠시 후 바로 그림에 반영되고, 포커스한 항목의 부품은 분홍 테두리로 강조됩니다.
- 레일·스테이지·갠트리·헤드를 이름/색상으로 구분하고 mm 치수와 위치, 헤드 Y 이동 범위를 표시합니다. 미리보기에서도 확대·스크롤·화면 맞춤을 사용할 수 있습니다.
- 제약을 위반해도 미리보기는 계속 그리며, 위반 항목·현재 값·허용 범위를 목록으로 표시합니다. 헤드/스테이지가 범위 밖에 있어도 화면에 포함합니다. **적용**을 누를 때 위반이 남아 있으면 차단하고 설정 창을 유지합니다. 취소하면 현재 프로젝트와 시뮬레이터를 변경하지 않습니다.
- 역전 범위/음수 치수는 미리보기 외곽을 절댓값으로 그리며, 크기가 0이면 작은 위치 표시로 그립니다. 입력값을 자동 수정하거나 유효한 설정으로 취급하지 않습니다. 숫자를 입력 중이거나 표시 불가능한 수치라면 해당 항목의 마지막 표시 가능 값을 사용하고 별도 안내합니다. 실제 적용·저장·계산에는 기존 제약을 그대로 검사합니다.

## 장비 구조
- 갠트리는 고정 구조물이며 X축으로 이동하지 않습니다.
- Rail 1과 Rail 2는 고정된 레일입니다. 그 위에서 Stage 1과 Stage 2가 각각 독립적으로 X축 이동합니다. 스캔 시에도 레일은 고정이며 스테이지 본체가 움직입니다.
- 스테이지 X 좌표는 본체 중심 위치입니다. 각 스테이지의 X 길이와 Y 폭, 각 레일의 X 시작/끝 및 공통 Y 폭을 mm로 설정합니다. 본체가 레일 끝으로 돌출되는 모습도 화면에 포함합니다.
- Scanner Head는 Y축으로 1열과 2열 사이를 이동합니다. 해당 열의 스캔 중에는 Y 위치를 유지합니다.
- 모든 축 위치와 설비 치수는 **mm**입니다. 초기 설정은 X/Y 0–100 mm, 1열 Y=0 mm, 2열 Y=100 mm이며 설비 설정에서 이동 범위·열 위치·각 축 초기 위치를 변경할 수 있습니다. 100 mm를 넘는 위치나 음수 좌표도 설정한 이동 범위 안에서 사용합니다.

## 작업 편집과 병렬 실행
- 작업 그리드의 **누적 시간(s)**은 사이클 시작부터 해당 작업 완료까지의 시간(계산된 종료 시각)입니다. 단순한 행별 시간 합계가 아니며 병렬 실행·자원 대기를 반영해 타임차트와 일치합니다. 병렬 작업은 앞 행보다 작은 값일 수 있습니다. 읽기 전용, 소수점 세 자리까지 표시하며 계산 오류 시 `—`로 비웁니다. 추가/삭제/이동/편집/불러오기 후 재계산할 때 갱신하고 입력 JSON에는 저장하지 않습니다.
- 장비를 Stage 1/Stage 2로 선택하면 축 시작·끝은 X 위치, Scanner Head로 선택하면 Y 위치입니다. `이동`을 선택한 작업만 해당 축을 움직입니다.
- 스테이지의 스캔 작업은 `헤드 사용`을 선택합니다. 스테이지와 단일 헤드를 동시에 점유하므로 스캔 중 헤드 이동이나 다른 스캔이 겹치지 않습니다. 이동 없는 노광/대기도 헤드를 점유할 수 있습니다.
- 헤드의 열간 이동은 `Scanner Head`, `이동` 선택, Y 시작/끝과 소요시간으로 별도 입력합니다. 이 작업에는 `헤드 사용`을 선택하지 않습니다.
- `이전 완료 대기`를 해제하면 시간 0부터 자원이 가능한 가장 이른 구간에 배정합니다. 선택하면 바로 이전 행 완료를 기다립니다. 전체 앞선 행에 대한 장벽은 아닙니다.
- 목록 순서는 자원 배정 우선순위입니다. `위로/아래로`로 변경하며, 이동/삭제 시 이전 행 관계도 바뀝니다. 전역 최적화나 임의 선행 작업 그래프는 아직 없습니다.
- 모든 자원을 전체 작업 구간 [시작, 종료)에 예약합니다. 독립 작업은 기존 예약 전의 빈 구간에도 들어갈 수 있습니다.
- 각 축의 이전 종료 위치와 다음 시작 위치가 다르거나, 스캔할 열에 헤드가 없으면 계산 오류를 표시합니다. 복귀/Y 이동을 추가하거나 순서·이전 완료 대기를 조정하세요. 엔진이 위치 전환을 자동 생성하지는 않습니다.

## 화면과 예제
작업 편집기는 왼쪽 위, 시뮬레이터는 오른쪽 위, MCC 타임차트는 하단 전체 폭입니다. 연한 타임라인 막대는 스테이지 스캔에 의한 헤드 점유를 표시합니다.

시뮬레이터에서 회색 갠트리는 고정되고 스테이지는 수평, 헤드는 수직으로 움직입니다. 스캔 중 헤드는 빨간색입니다. 대기/종료 시 마지막 위치를 유지하며 재생 시간은 단조 시계를 사용합니다.

기본 예제는 Stage 2 로딩과 Stage 1 작업을 병렬 실행하고, Stage 1 스캔 후 헤드 Y 이동과 Stage 1 X 복귀도 겹칩니다. 모든 축의 초기 위치 복귀까지 포함해 순차 시간 합계 50.75초, 계산된 사이클 39초입니다. 헤드의 왕복 Y 이동과 Stage 2 X 복귀를 포함합니다.

## 시뮬레이터 확대와 시간 탐색
- 시뮬레이터는 기본 200%로 표시합니다. 확대 슬라이더에서 100~400%를 선택하고 **화면 맞춤**으로 100%로 돌아갑니다.
- 확대 시 도형과 글자를 함께 키우고 X/Y의 mm 비율을 유지합니다. 가로·세로 스크롤바로 설비의 다른 부분을 볼 수 있습니다. 확대율 변경 시 보고 있던 중앙을 유지합니다.
- MCC 차트의 빨간 선이나 차트 배경/막대를 클릭하고 드래그해 시간을 탐색합니다. 스크롤된 Canvas 좌표를 사용하므로 가로 스크롤 뒤에도 같은 시각을 가리킵니다. 차트 양끝을 넘으면 0~사이클 종료 시간으로 제한합니다.
- 탐색하면 재생은 일시정지되고 스테이지/헤드 위치가 즉시 갱신됩니다. **재생**으로 선택 시각부터 이어갑니다. 재생을 시작하기 전에도 탐색할 수 있으며 이 경우 첫 사이클의 선택 시각에서 시작합니다.
- 반복 재생을 탐색할 때는 현재 사이클 번호를 유지하며, 누적 시간과 완료 횟수는 선택한 시뮬레이션 시점에 맞춰 갱신됩니다. 마지막 끝점에서 다시 재생하면 첫 사이클부터 새로 시작합니다.
- 시간 탐색은 저장된 작업의 시간/위치를 수정하지 않습니다. 반복 운전의 복귀 위치 검사도 계속 적용됩니다.

## 연속 사이클 재생
- 반복 횟수는 **총 실행 횟수**입니다. 기본 1회이며 1~1,000,000회까지 지정할 수 있습니다. `무한 반복`을 선택하면 중지할 때까지 반복합니다.
- 2회 이상 또는 무한 반복 시, Stage 1 X / Stage 2 X / Head Y의 최종 위치가 설비 설정의 각 초기 위치와 같은지 검사합니다. 다르면 재생을 시작하지 않고 복귀가 필요한 축과 위치를 상태줄에 안내합니다. 기존 프로젝트에는 필요한 복귀 작업을 직접 추가하세요.
- 기본 예제는 복귀 작업을 포함하므로 바로 반복할 수 있습니다. 복귀 시간도 사이클 시간에 포함되며 경계에서 위치를 순간 이동시키거나 시간을 추가하지 않습니다.
- `일시정지` 후 `재생`은 같은 사이클과 누적 시간에서 이어집니다. `중지`는 현재 위치와 카운터를 유지하고 재개 대기를 해제합니다. 중지/완료 후 다시 `재생`하면 첫 사이클부터 새로 시작합니다.
- `처음으로`는 시간, 위치, 완료 횟수를 초기화합니다. 작업/설비 재계산이나 반복 설정 변경도 진행 상태를 초기화합니다. 재생/일시정지 중에는 반복 설정을 잠그며, 설정을 바꾸려면 먼저 중지하세요.
- 현재 사이클 번호, 완료 횟수, 전체 누적 시간을 표시합니다. 차트 커서는 현재 사이클 내부의 시간이며 마지막 지정 횟수가 끝나면 차트 끝에 멈춥니다.
- 반복 횟수와 무한 반복 선택도 JSON에 저장합니다. 이전 파일에 해당 설정이 없으면 1회로 읽습니다.
- 사이클 안에서는 기존 병렬 작업을 유지하지만, 사이클 간 작업은 겹치지 않습니다. 연속 생산 파이프라인 최적화는 후속 범위입니다.

## 설비 설정 (mm)
시뮬레이터의 **설비 설정 (mm)** 버튼을 누르세요.
- Rail 1·2 각각의 X 시작/끝과 공통 Y 폭, Stage 1·2 각각의 X 길이·Y 폭을 입력합니다. 기본 스테이지는 20×20 mm, 레일 폭은 4 mm입니다.
- Stage X 최소/최대와 각 Stage 초기 X, Head Y 최소/최대와 초기 Y, 1·2열의 Y 위치를 입력합니다. 스테이지 중심의 이동 범위는 두 레일의 X 범위 안이어야 합니다.
- 갠트리 X/Y 시작·끝을 입력해 고정된 몸체 외곽을 지정합니다. 기본 X 외곽은 요청한 20–60 mm이며 Y 외곽은 -15–115 mm입니다.
- 헤드 고정 X는 중심 위치이며, 폭(X)·높이(Y)를 입력합니다. 기본 X=40 mm, 폭 8 mm, 높이 12 mm입니다. 헤드 Y는 초기 위치에서 작업 궤적을 따라 움직입니다.
- 헤드 외곽과 전체 Y 이동 범위는 갠트리 외곽 안에 있어야 합니다. 예를 들어 Y 이동 범위를 확장하면 갠트리 Y 외곽도 함께 확장하세요.
- 적용 시 재계산합니다. 기존 작업 좌표를 자동으로 늘리거나 옮기지 않으므로 열 위치/초기 위치/범위를 바꾼 경우 작업의 시작·끝도 맞춰 주세요. 취소하면 기존 설정을 유지합니다.
- 화면은 X/Y에 같은 mm 축척을 적용하며 창 크기에 맞춰 전체 설비를 표시합니다. 갠트리/헤드 툴팁에 외곽 mm 좌표가 표시됩니다. 스테이지 본체도 설정한 mm 길이·폭으로 표시합니다. 레일 이름은 고정되고 Stage 이름과 중심 표시는 본체와 함께 이동합니다.

## 저장 형식
JSON은 `FormatVersion: 3`, `Units: mm`, `AxisModel: FixedGantry_StageX_HeadY`, `Machine`, `Operations`를 가진 객체로 저장합니다. 설비 치수와 위치, 헤드 사용/병렬 설정을 함께 보존합니다. 저장 전 검증하고, 불러온 데이터도 검증한 뒤 기존 목록을 교체합니다.

레일/스테이지 치수가 없는 기존 mm 프로젝트는 레일의 X 범위를 기존 Stage X 최소/최대에서 가져오며, 스테이지 크기는 기본값을 사용합니다. 작업 좌표와 스케줄은 그대로 유지합니다. 저장할 때 추가 치수도 함께 보존합니다.

직전 버전의 FormatVersion 2 프로젝트는 기존 좌표값을 변경하지 않고 **1단위=1 mm**로 읽습니다. 화면 상태줄에 안내하며, 실제 치수에 맞춰 설비 설정과 작업 위치를 확인해야 합니다. 읽기만으로 원본 파일을 덮어쓰지는 않습니다.

이전 버전의 작업 배열 중 스테이지 작업은 읽을 수 있습니다. 이전 `Gantry / Head` 작업은 갠트리 X축을 움직이는 다른 모델이므로 자동으로 Y축으로 재해석하지 않습니다. 해당 파일은 명확한 오류를 표시하며 현재 프로젝트와 원본 파일을 보존합니다. 새 구조에 맞춰 스테이지 X 스캔과 헤드 Y 이동으로 다시 구성해야 합니다.

## 검증
- Windows: `dotnet build MccDesigner.sln` 후 실행 및 화면/조작 검증.
- Linux 컴파일: `dotnet build MccDesigner.App/MccDesigner.App.csproj -p:EnableWindowsTargeting=true`. WPF 화면 실행에는 Windows가 필요합니다.
- 계산 회귀 검사: `dotnet run --project MccDesigner.Tests/MccDesigner.Tests.csproj`. 실패 시 오류 코드로 종료하는 외부 패키지 없는 검사 프로그램입니다.
- 검사 범위: 소수점 시간, 병렬 자원 점유, 빈 구간 배정, Stage X/Head Y 보간, 위치 연속성, 열 전환 선행 조건, 버전별 JSON, 잘못된 입력과 시간 오버플로.

빌드 산출물 bin/obj는 Git 추적에서 제외돼 있고 `.gitignore`에 포함됩니다.

현재 이동은 고정 시간 기반 선형 보간입니다. 가감속·저크 제한, 전체 선행 관계 편집과 Excel 연동은 후속 작업입니다. 본 프로그램은 설계 검토용이며 실제 장비 제어/안전 시스템이 아닙니다.
